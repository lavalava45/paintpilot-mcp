# build-process-video.mjs

Короткая инструкция по сборке общего process-video из записанных PaintPilot-фрагментов.

## Где лежит скрипт

```text
scripts/dev/build-process-video.mjs
```

Запускать удобнее всего **из корня репозитория**:

```text
E:\Downloads\devspace-test\experiments\photoshop-mcp-digital-painting
```

## Базовый запуск

Пример для текущего run:

```powershell
node scripts/dev/build-process-video.mjs processes/autumn-temple-process/run-02 --slowdown 4 --min-clip-duration 4
```

Или с собственным именем выходного файла:

```powershell
node scripts/dev/build-process-video.mjs processes/autumn-temple-process/run-02 --slowdown 4 --min-clip-duration 4 --name process-video-x4-min4
```

## Что он использует

Внутри указанного run скрипт ожидает такую структуру:

```text
export/
  manifest.json
  videos/
    0001_....mp4
    0002_....mp4
  frames/
    0001_....txt
    0002_....txt
```

Порядок клипов берётся из `export/manifest.json` по полю `sequence`.

Для каждого видео скрипт ищет одноимённый `.txt` в `export/frames/` и использует этот текст как титр для соответствующего фрагмента.

## Как работает

1. Через `ffprobe` определяется реальная длительность каждого исходного клипа.
2. Если задан `--slowdown 4`, видео замедляется в 4 раза.
3. Если после замедления клип короче `--min-clip-duration`, последний кадр удерживается до заданной минимальной длительности.
4. Все обработанные клипы склеиваются в одно видео.
5. Одновременно создаётся `.srt`: блоки комментария показываются последовательно, равными долями внутри соответствующего клипа. Обычно это намерение художника, способ работы в Photoshop и результат. Предложения внутри блока остаются вместе.
6. Дополнительно создаётся `timeline.json` с точными таймингами каждого фрагмента и его `subtitle_cues`. Время рассчитывается по реальной длительности обработанного клипа, включая замедление и удержание кадра.

Например, три блока в 12-секундном сегменте показываются по 4 секунды. Число блоков не ограничено тремя: учитываются пустые строки между абзацами и отдельный блок способа работы «В Photoshop я использую…» / «In Photoshop I use…». В старом тексте без таких разделителей используются непустые строки. Текст не сокращается и не разбивается на предложения. Соседние титры имеют общую границу с точностью до миллисекунды и не выходят за сегмент; если сегмент короче числа блоков в миллисекундах, соседние блоки объединяются без потери текста.

## Куда пишется результат

В:

```text
<run-dir>/export/final/
```

Например:

```text
processes/autumn-temple-process/run-02/export/final/
  process-video-x4-min4.mp4
  process-video-x4-min4.srt
  process-video-x4-min4.timeline.json
```

## Основные параметры

```text
--slowdown <factor>
```

Во сколько раз растянуть длительность видео. По умолчанию `1`.

```text
--min-clip-duration <seconds>
```

Минимальная длительность каждого итогового фрагмента. Если клип короче, скрипт удерживает его последний кадр. По умолчанию `0`, то есть функция выключена.

```text
--name <stem>
```

Имя итоговых файлов без расширения. По умолчанию `process-video`.

Дополнительно доступны:

```text
--crf <0-51>
--preset <ffmpeg-preset>
--keep-list
--help
```

## Рекомендуемый вариант

Для нынешних очень коротких Photoshop-записей:

```powershell
node scripts/dev/build-process-video.mjs <run-dir> --slowdown 4 --min-clip-duration 4
```

Это сохраняет видимое действие замедленным и даёт всему сегменту минимум 4 секунды; блоки комментария делят это время поровну. Если три блока нужно показывать минимум по 4 секунды, задай `--min-clip-duration 12`.

## Требования

Нужны доступные из командной строки:

```text
node
ffmpeg
ffprobe
```

На текущей рабочей машине `ffmpeg` и `ffprobe` уже установлены и доступны в `PATH`.
