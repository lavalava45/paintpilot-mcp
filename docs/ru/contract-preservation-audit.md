# Contract Preservation Audit — сохранение контрактов Guard

## Цель и основной инвариант

Поле, принятое публичной схемой `photoshop_guard_cycle_auto`, может сохраняться, преобразовываться в типизированный исполнительный контракт, использоваться только для проверки или сопоставляться с подтверждённым состоянием Guard. **Оно не должно бесследно исчезать на границе компилятора.** Успешная сборка и большое количество unit-тестов этого сами по себе не доказывают.

`src/core/guard/contract-preservation.ts` содержит явную карту судьбы **каждого именованного поля первого уровня** четырёх публичных поверхностей:

| Поверхность | Полей | Маршрут |
|---|---:|---|
| Конверт `cycle_auto` | 6 | Закрытие прошлой операции, retained review или новый запрос |
| `next_pass` | 62 | Семантика → владелец → технический контракт → геометрия → исполнение |
| `painting_intent` | 40 | Типизация → наследование владельца/метода → `next_pass` |
| `previous_observation` | 33 | Привязка к кадру → `previous_visual_verdict` → закрытие |
| **Всего** | **141** | Схема и карта должны совпадать без исключений |

Аудит рекурсивно перечисляет также именованные вложенные поля публичной схемы (сейчас 1375 путей); для них действует контракт соответствующего типизированного родителя. Новое поле первого уровня без документированной судьбы останавливает проверку. Три открытые структуры `args`/параметров инструментов нельзя достоверно перечислить заранее: их допустимость проверяется схемой выбранной Photoshop-операции.

### Допустимые судьбы поля

- **`retained`** — сохраняется смысловое значение поля в Guard или исполнительной операции.
- **`translated`** — преобразуется в типизированный метод, класс действия или параметры проверки, без выдумывания художественного решения.
- **`validated`** — проверяется Guard, но не обязано становиться параметром нативного Photoshop-инструмента.
- **`durable`** — сверяется с подтверждённым владельцем, сценой или изображением.
- **`conditional`** — применимо только для подходящего маршрута, например `restore_anchor_operation_id`.

Это полная **декларативная карта**, но не утверждение, что все возможные значения 141 поля прошли отдельное динамическое доказательство. Для наиболее опасных потерь добавлена исполняемая проверка.

## Проверка перед отправкой Photoshop

`criticalPreservationFailures()` проверяет **конечную** операцию после всех ограниченных исправлений компилятора. Он запрещает:

1. Потерю или изменение `next_pass.foundation_goal`.
2. Потерю любого указанного художником элемента `next_pass.change_domains`; Planner может добавлять обоснованные домены, но не удалять исходные.
3. Замену исходного `next_pass.document_id` другим документом.
4. Изменение `next_pass.action_class` внутри сформированного `VisualMicroPlan`.

Нарушение возвращает `contract_field_lost_during_compilation` с путём исходного поля. Это системный отказ **до исполнения**. При прямом `photoshop_delete_layer` метка `ROLLBACK` сама по себе не разрешает удаление и не подменяет подтверждённый Undo. Все проверки Stop, слоя, документа, истории и защищённых целей сохраняются.

## Регрессионная матрица

`tests/contract-preservation-audit.test.ts` и `tests/direct-foundation-domain-regressions.test.ts` проверяют оба профиля, наличие/отсутствие Art Director, прямую операцию и `VisualMicroPlan`, `painting_intent`, классы действия, закрытие точного предыдущего кадра, Stop и отказ для устаревшего якоря восстановления. Исторический случай с удалением ошибочного ореола на слое 16 воспроизводится **только на подставном инструменте**: настоящий Photoshop не изменяется.

Отрицательные контрольные тесты намеренно удаляют `foundation_goal`, `change_domains` или подменяют `document_id`. При таком дефекте проверка обязана падать. Отдельно проверяется полнота карты опубликованной схемы и отсутствие устаревших деклараций.

### Обязательная приёмка

`npm run verify:contract-preservation` проверяет собранную публичную схему и целевые тесты. Команда добавлена в `test:acceptance`, `verify:canonical` и `prepublishOnly`. Полный набор source-тестов по-прежнему запускается через автообнаружение Vitest.

**Границы доказательства:** аудит не утверждает, что модель действительно получила инструкцию, что Photoshop-мутация прошла успешно или что результат художественно хорош. Автоматическое доказательство смысловой эквивалентности всех вложенных параметров потребует дополнительных специализированных правил. Сейчас в runtime строго проверяются самые опасные переходы, а остальные поля получают явную судьбу и покрываются соответствующими тестами.
