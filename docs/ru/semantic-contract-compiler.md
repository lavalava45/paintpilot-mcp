# Семантический компилятор контрактов

Художник задаёт **художественное намерение**. PaintPilot до строгих проверок Guard и операций Photoshop преобразует однозначные технические зависимости в корректные ID, ссылки и привязки. Компилятор **не** выбирает композицию, освещение, цвет, геометрию или перенос владельца слоя вместо художника.

## Единый источник технических контрактов

Файл `src/core/guard/semantic-contract-spec.ts` содержит `SEMANTIC_CONTRACT_SPEC`:

- **Типизированные сущности:** модели сцены, источники света, геометрические компоненты, владельцы и объекты.
- **Типизированные ссылки:** локальный тональный якорь, атмосфера, ссылки на модели геометрии и владельцев.
- **Точные технические привязки:** ID документа, удостоверенная инкарнация, ревизии и источники данных.

`semantic-entity-registry.ts` разрешает их по общим правилам. Та же спецификация изменяет публичные JSON Schema для `next_pass` и `painting_intent`: технические ID становятся необязательными, если компилятор может безопасно их определить. `compileGuardCycle` запускает преобразование до проверки scene-моделей и повторяет его в ограниченной внутренней проверке.

## Намерение → владение → метод → исполняемый план

Общая декларация `SEMANTIC_EXECUTION_SPEC` и модуль `semantic-execution-compiler.ts` расширяют систему за пределы одних идентификаторов:

1. **Владение слоем:** явно выбранный `target_owner_id` связывается с единственным действующим долговременным `logical_layer` и его физическим слоем. Чужой заданный ID, несколько владельцев, ещё не созданный слой и межслойная миграция не исправляются догадкой. Сохраняются прежние проверки независимости и rollback.
2. **Контракт метода:** необходимые поля `paint_strategy` задаются в одном месте и используются также публичной схемой VisualMicroPlan. Материал берётся лишь из явного `material_role` либо из **единственного** проверенного материала выбранной кисти. Первое значение из нескольких вариантов не выбирается; несуществующие свидетельства не создаются.
3. **Исполняемый план:** отдельный детерминированный этап завершает техническую последовательность и при необходимости добавляет последний preview. Проверки VisualMicroPlan, Photoshop, Guard и оценка итоговых пикселей остаются обязательными.

Это устраняет **часть** блокировок отсутствующего владельца и некорректно собранного метода на уровне причины. Действительно чужие физические слои и неверные операции должны по-прежнему отклоняться.

## Доказательная диагностика происхождения ошибок

Модуль `contract-error-provenance.ts` добавляет к **каждому отказу на этапе компиляции Guard** машинно-читаемый `contract_error_provenance`. Отчёт составляется в рамках той же попытки до изменения Photoshop и не подменяет существующие коды ошибок или решение Guard.

Наблюдатель сопоставляет поля исходного запроса, этапов идентичности, владения, проверенных привязок, геометрии, сформированной операции и её валидации. Для каждого отказа доступны путь поля (когда он определён), этап, наличие/тип и HMAC-SHA-256 значения в пределах одной попытки. Исходное художественное задание, данные изображений и полные аргументы в этот отчёт не записываются. В журнал сохраняется лишь проверенная ограниченная проекция, а краткая сводка последнего отказа доступна из истории попыток.

- `authored_conflict_with_durable_binding`: заданный в исходном запросе числовой слой доказуемо противоречит единственной подтверждённой привязке владельца.
- `durable_owner_binding_absent`: художник запросил продолжение работы с владельцем, которого нет в зарегистрированном журнале.
- `compiler_output_invalid`: техническое значение появилось только при компиляции либо ошибочная структура принадлежит сформированному сервером `next_operation`.
- `contract_spec_conflict` / `compiler_pipeline_failure`: противоречивые требования Guard или отсутствие исполняемой операции — системная проблема.
- `input_field_present`, `input_field_missing`, `unattributed`: доказано только происхождение поля; первопричина не установлена.

Принципиальное ограничение: `instruction_delivery: "not-observed"` и `model_instruction_noncompliance_proven: false`. MCP не видит, какие инструкции реально доставлены модели, прочитаны ли они и почему она выбрала определённые значения. **Некорректный запрос не является доказательством сознательного игнорирования инструкции.** Ошибки после фактического исполнения Photoshop и неопределённое состояние Undo/recovery остаются вне этой трассировки *preflight*.

Диагностика не создаёт разрешения на ретаргетинг слоя, изменение кисти, автоматический повтор или исполнение операции: Guard по-прежнему окончательно проверяет безопасность.

**Guard остаётся окончательным арбитром безопасности.** Компилятор не предоставляет полномочия изменять слой, не подтверждает качество пикселей, не снимает запрет повтора неизвестной операции и не ослабляет Undo.

## Пример

При описании сцены с одним источником света художник вправе не писать `id`, `model_id`, `revision` и `source_frame`. При наличии достоверного состояния текущего документа компилятор присваивает стабильные технические ID, связывает их с объектами и наследует доказанную инкарнацию документа.

Текст в `local_value_anchor` превращается в ссылку на объявленный источник, **только если он единственный подходящий**. Два возможных источника приводят к запросу художественного выбора; неверный явно указанный ID не переписывается. RGB-измерения не придумываются.

## Общие инварианты

1. Существующие ID сохраняются, новые вычисляются детерминированно в области конкретной инкарнации документа.
2. Две неразличимые декларации без собственной идентичности отклоняются; порядок элементов массива не подменяет идентичность.
3. При обновлении модели используется её точная долговременная идентичность и очередная ревизия, если эти сведения однозначны.
4. Чужие ссылки, устаревшие свидетели документа и явные конфликты не исправляются произвольной подстановкой.
5. Компилятор не выполняет Photoshop-операции и не регистрирует отклонённые декларации в долговременном состоянии.
6. Недостающие художественные решения и неподтверждённые измерения остаются обязательными — не превращаются в «успешную» компиляцию.

## Как расширять

Чтобы подключить новый технический тип, добавляют описание сущности, ссылки или привязки в `SEMANTIC_CONTRACT_SPEC` и тестируют её успешное, неоднозначное и ошибочное разрешение. **Отдельный `if` для каждого поля в preflight больше не является основным способом развития системы.**

Текущая реализация покрывает основные идентичности освещения/цвета, геометрии, камеры и владения компонентами. Она не распознаёт произвольный художественный текст как гарантированно верное физическое соответствие, не восстанавливает отсутствующие Photoshop-свидетельства и не гарантирует художественную завершённость `nontrivial_painting`.

Тесты: `tests/semantic-contract-registry.test.ts`, `tests/semantic-execution-compiler.test.ts`, `tests/contract-error-provenance.test.ts` и `tests/semantic-contract-end-to-end.test.ts`. Последние проверяют сам `compileGuardCycle` без отправки мутаций в Photoshop.
